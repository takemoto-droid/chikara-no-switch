# 検収のしかた

> この文書は、このプロジェクトの「検収」が何か（誰が、何を確かめるか）と、検収で実際に見つかって直した例を、便ごとにまとめたものです。
> 元の資料は、司令塔（相談役の Claude）の記録（資料リポジトリの `47_検収の結果と先生の判断_便27から36_20261108.md`。以下「資料 47」）と、各便の投げ文です。元の資料に無いことは「記録なし」と書き、想像で足していません。

## 1. 検収とは
- このプロジェクトでは、**本部（制作の Claude）が作り、司令塔（相談役の Claude）が検収し、先生が決めます。** 先生の言葉は、訳さずに投げ文に写して本部に渡します（資料 47）。
- 検収は「**動作確認＋実際の画面・動画のコマを見る**」ことです。テストが通ることと、数字・文が決まりどおりかを、司令塔が自分で動かして確かめます。動画は、2 秒おきのコマと、拡大したコマを見ます（資料 47）。
- 合格のしるしは、投げ文の「受け入れ条件」を 1 つずつ満たしているかです。満たしていない所や、新しく気づいた所は、次の便の投げ文に入ります。
- 合否を決めるのは司令塔の検収、直すかどうかを最後に決めるのは先生です。

## 2. 誰が、何を確かめるか

| 誰 | 何を確かめるか |
|---|---|
| 本部（制作の Claude） | push の前に、自動の確かめ（`npm test`：言葉の点検・比べ方の確かめ／`npm run toshi`：スマホと PC の幅で画面を最後まで通す）を通す。受け入れ条件ごとの結果を報告に書く |
| 司令塔（相談役の Claude） | main を取りこんで、自分でも `npm test`・`npm run toshi` を走らせる。公開デモを開いて最後まで押す。画面の文・数字・動画のコマを見る。受け入れ条件に照らして合否を出す |
| 先生 | 検収の結果を読み、直すか・そのままにするかを決める。公開デモや動画を自分で見て、気づいたことを言葉で伝える（その言葉が次の便のきっかけになる） |

- 検収では、Claude に**役を立てて**見させることがあります（例：総合プロデューサー・読みづらい視聴者・アプリ画面の設計者）。これは Claude が役を演じたもので、本物の専門家の意見ではありません（[専門家の意見について.md](専門家の意見について.md)）。
