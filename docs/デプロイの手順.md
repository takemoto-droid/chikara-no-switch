# 公開（デプロイ）の手順　―　先生のアカウントで Vercel に出す

> 2便で書き直した手順です。まだ公開はしていません。
> **API キーが無くても公開できます。** キーが無いあいだは、決まった順の「予備の動き」で、最後まで動きます。キーが来たら、あとから入れるだけです。

## 0. 用意するもの
- GitHub のアカウント（リポジトリ `chikara-no-switch` が見られるもの）
- Vercel のアカウント（無料の Hobby で足ります。GitHub のアカウントで登録できます）
- （あとで）Anthropic の API キー

## 1. Vercel にリポジトリをつなぐ（キー無しで公開）
1. https://vercel.com を開き、「Sign Up」または「Log In」で、GitHub のアカウントで入ります。
2. 右上の「Add New…」→「Project」を押します。
3. 一覧から `chikara-no-switch` を探して「Import」を押します。出てこないときは「Adjust GitHub App Permissions」で、このリポジトリを選べるようにします。
4. 次の画面は、ほぼそのままで大丈夫です。
   - Framework Preset：「Other」
   - Root Directory：そのまま（`./`）
   - Build Command・Install Command：さわらない（`vercel.json` に必要なことを書いてあります）
   - Environment Variables：**キー無しで公開するなら、何も入れません。**
5. 「Deploy」を押します。1〜2分で終わります。
6. 出てきたアドレス（`https://chikara-no-switch-〇〇.vercel.app` のような形）を開きます。
7. はじめの画面のいちばん下に「いまは Claude を使わず、決まった順の予備の動きで出しています。」と出ていれば、キー無しの公開ができています。

これで、審査の人も「保存した結果を見る」「その場で動かす」の両方を試せます。記録は見た人の端末のブラウザの中にだけ残り、サーバーには残りません。

## 2. キーが来たら（3便）
### 2-1. デモ専用の「ワークスペース」を作り、使う額の上限をかける
公開デモは、だれでも押せます。使いすぎを防ぐため、**デモ専用の入れ物（ワークスペース）を作って、その中でキーを作ります。**
1. https://console.anthropic.com （Claude Console）に入ります。
2. 「Settings」→「Workspaces」→「Create Workspace」で、たとえば「チカラのスイッチ公開デモ」を作ります。
3. 作ったワークスペースの「Limits」で、次の2つをかけます。
   - **使う額の上限**（月あたり）：たとえば数ドル。上限に達すると Claude が使えなくなり、アプリは自動で予備の動きに切りかわります（画面は止まりません）。
   - **回数の上限**（1分あたり）：小さめにします。
4. そのワークスペースの「API Keys」→「Create Key」でキーを作り、写しておきます。**このキーは、Vercel の画面にだけ貼ります。** メール・チャット・リポジトリには貼りません。

（Console の画面の名前は変わることがあります。見つからないときは、Console の「Limits」「Workspaces」の説明を見てください。）

### 2-2. Vercel にキーを入れる
1. Vercel のプロジェクトを開き、「Settings」→「Environment Variables」を開きます。
2. 次を入れて「Save」を押します。

| 名前（Key） | 値（Value） | 要るか |
|---|---|---|
| `ANTHROPIC_API_KEY` | 2-1 で作ったキー | 要る |
| `DEMO_KAISU_JOUGEN` | 1つの接続元が1時間に Claude を呼べる回数（たとえば `30`） | なくてもよい（決めなければ 60） |
| `CLAUDE_MODEL` | 使うモデルの名前 | なくてもよい（決めなければ `claude-opus-5-5`） |
| `CLAUDE_FUTSUU` | `1` にすると、試験的な機能を使わない「ふつうの呼び方」だけで呼ぶ | なくてもよい |

3. 「Deployments」で、いちばん上の行の「…」→「Redeploy」を押します（キーは、出し直したときから効きます）。
4. はじめの画面のいちばん下が「いまは Claude を使っています。」に変われば、できています。

### 回数・額の上限は2か所
- **アプリの中の上限**（`DEMO_KAISU_JOUGEN`）：1つの接続元ごとの目安です。サーバーの関数が立ち上がり直すと数え直すので、確実な上限ではありません。
- **Anthropic 側の上限**（2-1）：こちらが確実な上限です。必ずかけてください。
- どちらの上限に達しても、アプリは予備の動きで最後まで動きます。

## 3. 公開の前に確かめること（制作の側で行う）
- `npm test`：言葉の点検（画面・サーバー側・予備の動き・README）と、比べ方・Claude の呼び方の確かめ。
- `npm run toshi`：スマホの幅で ①〜⑥ を最後まで通し、各画面の文を点検する（Playwright と Chromium が要る）。
- キーが来たら：`TENKEN_CLAUDE=1 ANTHROPIC_API_KEY=… npm run tenken` で、Claude の出力にも避ける言葉が 0 件かを見る（キーは打ちこむときだけ使い、どこにも保存しない）。
- リポジトリに `.env`・API キー・個人のメールアドレス・実在の子どものデータが入っていない。

## 手元で動かす（制作の側）
1. Node.js 20 以上を入れて、`npm install`。
2. `npm start` → `http://localhost:8787`。キーを使うときは `.env.example` を `.env` に写してキーを入れる（`.env` は Git に入れない）。
3. キーがあっても予備の動きを試すときは `npm run start:yobi`。

## 作りの形（参考）
- 画面は静的なファイル（`public/`）。読み上げの音声も `public/onsei/` に前もって置いてある。
- サーバー側の関数は `api/[name].js` の1つ（中身は `lib/api.mjs`）。
- API キーはサーバー側の環境変数だけで読む。画面（ブラウザ）には渡さない。
- Cloudflare に出すときは、`lib/api.mjs` の JSON の読み方を変える必要がある（今は Vercel の形だけ）。
