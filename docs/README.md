# 文書の入口（docs/）

> この文書は、`docs/` の入口です。このリポジトリが何か、どの順に読めばよいか（人間向け・AI 向け）、`docs/` の全部のファイルの地図、このプロジェクトで使う言葉（便・投げ文・検収など）の意味を書いています。

## このリポジトリは何か
- 「チカラのスイッチ」は、困りごとを自分では言葉にできない中学生に「分かってもらえる機会」を作るウェブアプリです（Built with Claude: Japan 2026 の作品）。
- ホームルームの短いゲームで、同じ問題を出し方（読む・聞く・図で見る・区切る など）だけ変えて解き、力が出た出し方が「スイッチカード」として本人に残ります。先生には、配慮の手がかり（事実と、試した工夫）が残ります。
- 作者は先生（数学の教員）です。Claude は、調べる・作る（Claude Code）・アプリに組み込む、の 3 つの使い方で使いました。
- アプリの説明は、リポジトリの入口の [README.md](../README.md) にあります。この `docs/` には、作りの決まり・根拠・確かめ・制作の過程を置いています。

## 正直に書いておくこと
- **専門家の監修は、まだ受けていません。** 制作の中の「専門家会議」は、Claude が専門家の役を演じて検討したもので、本物の専門家の意見ではありません（[専門家の意見について.md](専門家の意見について.md)）。
- **画面の文・問題・Claude への頼み方などは、Claude が書いた下書き**で、先生が確かめて直します（[先生が確かめる一覧.md](先生が確かめる一覧.md)）。Claude がアプリの中で書く文（仮説・伝え方・計画）も、先生への下書きです。
- **データはすべて合成か架空です。** 架空の子 8 人の結果と、合成データ（計算で作った子）での確かめだけで、実際の子どもでの確かめはこれからです（[合成データでの確かめ.md](合成データでの確かめ.md)）。
- 書き分けの決まり：この `docs/` の新しい文書では、事実・先生の判断・Claude の提案を書き分けます。元の資料に無いことは「記録なし」と書き、想像で埋めません。

## 言葉の説明
| 言葉 | 意味 |
|---|---|
| **便**（びん） | 制作を進めた作業のまとまりの番号です。1便から順に数えました。「〇便」の表記は、どのように作り、直してきたかの証として、そのまま残しています。便ごとの一覧は [制作の流れ.md](制作の流れ.md)。 |
| **投げ文** | その便で本部に渡す注文書です。作る範囲・守ること・受け入れ条件と、先生の言葉の写しが入っています。資料リポジトリに番号つきで置いています。投げ文の番号と便の番号は別です（例：投げ文 46 ＝ 37便）。 |
| **検収** | 本部が作ったものを、司令塔が確かめることです。動作確認（テストを自分で動かす・公開デモを最後まで押す）と、画面・動画のコマを見ることが中心です（[検収のしかた.md](検収のしかた.md)）。 |
| **司令塔** | 先生の相談役の Claude（チャット）です。先生の言葉から投げ文を書き、本部の報告を検収します。はじめのころは「相談チャット」と呼んでいました。 |
| **本部** | 制作の Claude（Claude Code）です。コード・下書きの文・確かめを書き、自動の確かめを通してから main に入れ、報告します。 |
| **先生** | この作品の作者です。題材・作る範囲・言葉を決めます。決めるのは、いつも先生です。 |
| 伴走チャット | 11/4〜11/6 に、先生が細かいこと（副題・カードの名前・相談先の文など）を相談して決めた、別の Claude のチャットです。決まったことは、本部が直接 main に入れました（[先生の判断の記録.md](先生の判断の記録.md) の 2 章）。 |
| 資料リポジトリ | 投げ文・検収の記録・調査の文書を置いた、別のリポジトリ（chikara-no-switch-shiryo）です。学校名など公開しない情報を含む文書があるので、要る内容は、この `docs/` に書き直して載せています。 |
| フェーズ | 5便から、一つの便の中を小分けにした作業（F1・G2 など）です。[制作の記録.md](制作の記録.md) に、フェーズごとの記録があります。 |
| 13便のもと | 12便のあと、伴走チャットの決定を入れた作業と、次の便のための案です。「13便」そのものは出ていません。 |
| 凍結 | 11/6（20便）から、提出物を優先するために、機能を増やさないと決めたことです。例外は先生が決めました。 |
| 公開デモ | 先生のアカウントで公開しているアプリです。main に入れると、そのまま公開デモが変わります。 |
| 決まった文 | Claude を使わないとき（鍵が無い・呼べる回数の上限など）に出す、前もって用意した順と文です。制作の文書では「予備の動き」とも書いています。 |

## このプロジェクトの作り方
1. **先生**が、気づいたこと・決めたことを言葉にします（例：「文字が多くて一人でテストすることが難しい生徒もいるかも」）。
2. **司令塔**が、それを投げ文にします。先生の言葉は訳さずにそのまま写し、司令塔が足すのは、範囲・触るもの・受け入れ条件です。
3. **本部**が作ります。`npm test`（言葉の点検・比べ方の確かめ）と `npm run toshi`（スマホと PC の幅で画面を最後まで通す）が通ってから main に入れ、報告します。
4. **司令塔**が検収します（[検収のしかた.md](検収のしかた.md)）。
5. **先生**が、検収の結果と画面・動画を見て決めます。気づいたことが、次の便のきっかけになります。

## 人間が 5 分で読む順
1. [README.md](../README.md) の冒頭「はじめて見る人へ（3つだけ）」（1 分）：何をするアプリか。
2. この文書の「言葉の説明」（1 分）：便・投げ文・検収・司令塔・本部。
3. [制作の流れ.md](制作の流れ.md) の一覧（1 分）：どの順に作り、なぜ直したか。
4. [先生の判断の記録.md](先生の判断の記録.md) の 1 章（1 分）：先生が何を決めたか。
5. [検収のしかた.md](検収のしかた.md) の 3-1 と、[README.md](../README.md) の「8. 限界」（1 分）：何を確かめ、何がまだか。

## AI が読む順
上から順に読むと、迷わずに全体がつかめます。
1. [CLAUDE.md](../CLAUDE.md)：守ること（言葉・決めつけない・効果をうたわない・実在の子のデータを入れない など）。
2. [README.md](../README.md)：アプリの全体（困りごと・何をするか・仕組み・Claude の使い方・測った結果・限界・動かし方）。
3. この文書：`docs/` の地図と言葉。
4. [作り方の決まり.md](作り方の決まり.md)：問題・比べ方・カードの決まり。
5. [制作の流れ.md](制作の流れ.md) → [制作の記録.md](制作の記録.md)：便ごとの経緯と、フェーズごとのくわしい記録。
6. [先生の判断の記録.md](先生の判断の記録.md)・[検収のしかた.md](検収のしかた.md)：誰が何を決め、どう確かめたか。
7. [調べたこと.md](調べたこと.md)・[科学的根拠のあること_ないこと.md](科学的根拠のあること_ないこと.md)・[専門家の意見について.md](専門家の意見について.md)：根拠と、その限界。
8. [子どもの安全とプライバシー.md](子どもの安全とプライバシー.md)・[権利と出典.md](権利と出典.md)：安全と権利。
9. [data/言葉の正本.json](../data/言葉の正本.json)：避ける言葉と、画面に出さない制作側の言葉の一覧（点検に使う）。
- コードの場所：画面は `public/`、サーバー側（Claude を呼ぶ・言葉の点検）は `lib/` と `api/`、確かめと道具は `scripts/`（README の「5. Claude の使い方」「9. 動かし方」）。

## これからの便の残し方
- 本部は、便を終えるたびに [制作の記録.md](制作の記録.md) に書くのに加えて、[制作の流れ.md](制作の流れ.md) に 1 行足します。
- 司令塔の検収の結果と先生の判断は、司令塔が資料リポジトリに書きます。次の便の投げ文に「docs/ に写す」が入るので、本部はそのとおりに [検収のしかた.md](検収のしかた.md)・[先生の判断の記録.md](先生の判断の記録.md) に足します。
- `docs/` にファイルを足したら、この文書の地図にも 1 行足します。
