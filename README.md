# チカラのスイッチ

> 下書き（先生未確認）。副題は先生が決めます。【あとで書く】の所は、先生が書く所です。

困りごとを自分では言葉にできない子に、「分かってもらえる機会」を作るアプリです。
中学生がホームルーム（HR）の短いゲームで、力が出た出し方を見つけ、「スイッチカード」として手元に残します。朝の時間には、得意な出し方を支えにして、もう一方の出し方を育てる練習をします。先生には、配慮の手がかりが残ります。

「学び方の型を当てる」ものではありません。同じ問題を出し方だけ変えて解いてみて、**どの出し方のとき力が出たか**を、本人の結果で確かめます。医療や専門の検査の代わりでもありません。その手前を受け持ちます。

---

## 1. 困りごと

**困っていたのに、機会がなければ、何も解決せずに過ぎていく。**

「困ったら言ってね」と言っても、自分から言える子はほとんどいません。でも、たくさん質問すると答えてくれます。解けているのにノートは白紙、国語は苦手でも図は描ける――そういう子は、どの教室にもいます。

- 文部科学省の2022年の調査では、通常の学級の小中学生のうち、学習面や行動面で著しい困難があると担任などの教員が回答した子は、推定 8.8%（中学校は 5.6%）でした。そのうち、校内委員会で特別な教育的支援の対象とされているのは 28.7% です。
  - この数字は教員の回答にもとづく推定で、医師の判断にもとづく数ではありません。
- 専門の医療機関では、初診まで数か月待つことがあります。総務省の2017年の調査では、半数以上の機関で3か月以上待ち、最長は約10か月でした。
- 制度の上では、医師の判断がなくても配慮はできます。文部科学省は、通級による指導を決めるとき、医学的な判断があるかどうかだけで決めず、総合的に考えるよう求めています（2013年の通知）。でも現場では、根拠がないと動けません。
- 個に応じた指導は、気づいた先生には当たり前です。でも学校全体では、まだ当たり前になっていません。

**なぜ今まで解けていないか**：専門の検査は少数の子にしか届かず、子どもは困りを言葉にできず、先生の気づきには根拠が無いからです。

**学校の時間の中で、全員に届ける理由**：作者の前の授業での記録では、使った18人のうち11人が、授業の時間の中だけで使っていました（集計だけ）。家や休み時間に頼る形では、届かない子がいます。だから、HR と朝の時間の中のゲームと練習にしました。

【あとで書く】作った先生の実例（卒業生の話・解けているのにノートは白紙の子。した事実で書く）。

## 2. 何をするか

「見つけて、育てて、また見つける」の一本の道筋です。教科の授業には持ちこみません（評価のように受けとられないように）。ホームルーム（HR）と、朝学習・朝読書の時間を使います。同じ難しさの問題を、出し方だけ変えて解きます。一つ一つの出し方を「スイッチ」と呼びます。

1. **案内**：何をするか、何をしないかを、子どもと保護者に先に伝えます。AI を使っていることも伝えます。
2. **見つける（HR）**：「読む／聞く」「文で見る／図で見る」「連絡を一気に読む／一文ずつ区切って読む」の3つの組と、選んで答える質問に取り組みます。問題の難しさは、はじめの練習の結果で、その子に合う段階を選びます（比べるのは同じ段階の中だけ）。次に何を出すか・どの段階にするかは、Claude が理由をつけて選びます。途中に休みの画面があり、止めて続きから再開できます。
3. **スイッチカード**：力が出た出し方が、カードとして本人の手元にたまります（強みだけ・全員に1枚以上・見つからなければ「どれでも」・枚数は出さない）。カードには、比べた2つの出し方と、レベル（みつけた → たしかめた → しっかり）を添えます。カードは「出し方の3つの比べ」だけを表すもので、得意・不得意の全体は、先生の画面で結果・答え・観察を合わせて見ます。
4. **先生の画面**：その子の中での比べ方（比べた段階も事実で）、選んだ答え、チェック項目で当てはまったこと、練習の記録、Claude の仮説（理由つき・参考程度）、学校の設定と期間の計画を見ます。
5. **伝え方**：懇談で先生が口で言うための下書き、カードの保護者向け説明、学年・教科の先生への一言、HR の冒頭で先生が話すことを、Claude が下書きします。決めるのは先生です。
6. **育てる（朝の練習）**：得意な出し方を支えにして、もう一方の出し方を、支えを少しずつ減らしながら練習します（足場かけ → 足場外し）。段が上がるのは、ゲームの中の事実（2回続けて正解が多い など）だけです。「今日はやらない」も選べます。練習を始めると「そだてちゅう」のカードが現れ、段がそのままレベルになります。
7. **また見つける**：学校の設定の間隔（月1・2か月・学期）で、②の短い版（3つの組・前回と同じ段階から）をします。差が縮んだ出し方は、育てたカードが一人前になります。見つけたカードのレベルが上がります。カードは増えるだけで、消えません。

子どもには、力が出たことだけが残ります。他の子との比べっこはしません。

### これから（ビジョン）
- **先生の間の引き継ぎ**：年をまたいで、どの出し方を試し、どうだったかが分かる記録にします（**Should**：先生の画面の「引き継ぎの記録を書き出す」で、回ごとの日付・年度・差の向きを並べたファイルを作れます）。
- **同じ言葉で話す**：担任・教科の先生・保護者が、カードの言葉（「きいてスイッチ」など。名前は仮で、先生が決めます）で同じことを話せるようにします。
- **学校ごとの設定で回る**：HR の長さ・朝の練習の長さ・頻度・カードの更新の間隔を、学校ごとに決められます。Claude が、その設定とクラスの結果から、期間の計画を下書きします。
- **専門の相談先へ**：試した配慮や練習とその結果の記録を、相談に持っていける材料にします。
- **小学生・高校生・大人へ**：同じ考え方で、ほかの年代にも広げます（**Should**：はじめの画面の「大人が自分で試す」から試せます）。
- **出し方の比べを増やす（展望）**：「時間を決めた／決めない」の棚（じっくりスイッチ）、「見る／動かす」の出し方（図を触って合わせる）、「口で答える」の出し方。どれも、比べる棚を自作してからにします。
- **速さは評価しません。** かかった時間は、端末・読み上げの再生・その日の様子で大きく変わり、速さを比べると「早く解けない子」という見え方になりやすいためです。時間は先生の画面に参考として出すだけで、比べる数にもカードにも使いません（起点は、3つの棚とも問題が画面に出たとき）。
- 期間中に作るのは、この一部です。

**テーマとの対応**：テーマ2「本来、誰にでも届くべきものを」。専門の機関でしか受けられなかった「見つける・育てる」を、必要な子なら誰にでも届けます。

## 4. 仕組み（Claude の三段の役割）

| 段 | だれが決めるか | 内容 |
|---|---|---|
| 次に何を出すか | Claude | 問題の棚は固定（先生が確かめた自作）。結果を見て、次に試すスイッチを理由つきで選ぶ。理由は画面に出す |
| 仮説を出す | Claude | ゲームの結果・選んだ答え・チェック項目を並べて読み、「〇〇のとき力が出ているかも。次に試すなら△△」と書く。決めつける言葉は使わない。仮説・確かめた回数・参考程度を必ず添える |
| 言葉を書く | Claude（決めるのは先生） | カードの文、先生の口頭の下書き、保護者向けの説明、学年・教科の先生への一言、HR の冒頭の話。言葉の正本で機械的に点検し、避ける言葉が出たら書き直す |
| 計画を立てる（7便） | Claude（決めるのは先生） | 学校の設定（HR の長さ・朝の練習の長さと頻度・また見つけるの間隔）とクラスの結果から、次の「また見つける」までの計画（誰に・どの出し方・どの段から・何日ほど）を書く。名前は送らず、「子1」などの仮の番号だけを送る |

朝の練習（⑥）では、Claude は今日育てる出し方を候補の中から選び、理由を画面に出します。**段（支えをどこまで減らすか）は Claude が決めません。** 練習の中の事実（同じ段で「正解が多い」ひとつが2回続いた）だけで進みます。

**Claude でなければできない理由**：困りを言葉にできない子と、専門家ではない先生のあいだで、「たくさん質問する」ことを肩代わりし、結果・選んだ答え・チェック項目を並べて読んで、根拠つきの仮説と、保護者や先生に伝える言葉を用意します。決めるのは先生です。

### 研究にもとづく作り（くわしくは [docs/作り方の決まり.md](docs/作り方の決まり.md)）
- 測る問題は固定（先生が確かめた自作の棚）。練習は比べる数に入れない（**Should**：練習問題は、キーがあるときは Claude が作り、言葉の正本と形で点検してから使います。キーが無いときは決まった練習問題です）。
- 初回の1組は練習扱い。出し方の順は ABBA で入れ替え、どの文章をどの出し方で出すかも入れ替える。
- 読み返し・聞き返しの条件をそろえる（見返しは1回まで）。読み上げは前もって作った同じ音声。
- 「候補」は、同じ出し方を2回やったときの揺れより大きい差が、同じ向きに2回出たときだけ。別の日にも同じ向きの差が出たら「くり返し出た候補」。
- 難しさの段階をその子に合わせ、比べるのは同じ段階の中だけ（7便）。段階は子どもに見せない。
- 測る問題は固定、練習は流動（7便）：朝の練習の文は、測る棚とは別の練習の文（`public/data/renshu.json`）を使い、本番の比べに混ざらないようにする。
- 練習は足場かけ → 足場外し（7便）：得意な出し方を支えにして、支えを少しずつ減らす（段1〜4）。段が進むのは「同じ段で、3分の2以上正解のひとつが2回続いた」ときだけ（読む・聞くの段3 は、さらに支えのボタンを押したのが2回以下）。下がらない。脳トレのように別の課題で練習して広く効くことを期待するのではなく、育てたい出し方そのものを練習する。言えるのは「ゲームの中で、支えが少なくてもできる量が増えた」まで。
- 練習の中身は、06 の 4-A の4つの形（聞いて動かす・文と図・区切り・言葉にする）の範囲だけ。間違い探し・覚えて答える・目で追う形は入れない（既存の検査に似るため）。
- 他の子・学年・年齢とは比べない。数値の点を出さない。出すのは能力の値ではなく、出し方を比べた結果。カードのレベルはカードごとで、合計・順位・枚数を出さない。

### 画面の流れ
① 案内（子ども・保護者）→ ② 見つける（HR・端末の中に記録）→ ③ スイッチカード → ④ 先生の画面（まとめ・Claude の仮説・選んだ答え・チェック項目・練習の記録・数字の根拠・設定と計画）→ ⑤ 伝え方 → ⑥ 育てる（朝の練習）→ ⑦ また見つける（短い HR）。Claude はサーバー側の関数から呼び、出力は言葉の正本で点検してから画面に出します。

## 5. Claude の使い方

- 言葉の正本（[data/言葉の正本.json](data/言葉の正本.json)）を Claude に持たせます。避ける言葉が出力に出たら機械的に見つけ、書き直させます。
- 子どもが自由に文を打って Claude と会話する入口はありません。質問は選んで答える形です。
- AI を使っていることは、画面に表示します。
- 先生の画面の言葉も、保護者が読んで傷つかない言葉で書きます（事実・試した工夫・その結果）。
- キーが無いとき・使えないときは、決まった順・決まった文の「予備の動き」で最後まで動きます。
- **② 見つけるの問題は、固定の棚から出します。鍵があっても、Claude は問題を作りません。** Claude が変えるのは、次に出す棚・難しさの段階と、その理由だけです。問題を毎回作らせると、正解の差が「出し方の差」なのか「問題の差」なのか分からなくなるためです。そのため、予備の動きでも鍵があっても、出る問題は同じ系統になります（作りとして、そうしています）。Claude が文を作るのは、比べる数に入れない「はじめの練習」の問題だけです（**Should**・鍵があるときだけ・言葉の正本と形で点検してから使う）。朝の練習（⑥）の文も、決まった練習の文（`public/data/renshu.json`）から出します。
- **Claude の文は端末に覚えます**（10便）。公開デモは Claude を呼べる回数に上限があるので、先生の画面・伝え方・計画を開き直したときは、覚えた文を出し、Claude を呼びません。呼び直すのは「もう一度書いてもらう」を押したときと、ゲームの回・練習の記録・チェック項目・学校の設定のどれかが変わったときだけです。予備の動きの文は覚えません。
- **架空の子8人の Claude の文は、2026-11-04 に Claude が実際に書いたものを保存しています**（11便・`public/data/demo_claude.json`）。仮説・伝え方（懇談・保護者向け・一言・HR の冒頭）と、クラスの期間の計画です。公開デモで開いても Claude を呼ばず、「もう一度書いてもらう」で呼び直せます（呼び直した文は端末に覚え、保存した文は書きかえません）。保存した文は、人が手を入れていません。言葉の正本での点検は 0 件で、仮説には「仮説」「確かめた回数」「参考程度・決めるのは先生」がそろっています（`npm test`）。

| **Should**：練習問題を Claude が作る | ゲームの練習の2問（キーがあるときだけ。「この問題は Claude（AI）が作りました」と出す。比べる数には入れない） |
| **Should**：大人用の入り方 | はじめの画面の「大人が自分で試す」（記録はクラスのチェック項目に出さない） |

### 人が決めた所（先生と相談チャット）
- **題材と、だれのための何か**：困りごとを自分で言葉にできない中学生に「分かってもらえる機会」を作ること。
- **守ること**：避ける言葉（言葉の正本）、決めつけないこと（型や結論の名前を付けない）、効果をうたわないこと、子どもが自由に文を打つ入口を作らないこと、実在の子のデータを入れないこと、既存の検査に似る形を置かないこと。
- **ゲームの棚**：読む／聞く・文で見る／図で見る・一気に／区切って・選んで答える質問（制作の入口 06 の3章。棚 E は作らない）。
- **カード**：強みだけ、全員に1枚以上、枚数は出さない、「〇〇スイッチ」の名前、「この日の」結果だと分かる書き方（06 の4章）。
- **チェック項目**：18項目（06 の5章）。点数にしない。
- **比べ方の決まり**：本人の中だけで比べる、初回は練習、ABBA、揺れより大きい差が2回で「候補」、回をまたぐときは別の日の「くり返し」（[docs/作り方の決まり.md](docs/作り方の決まり.md)）。
- **どこまで作るか・何を後にするか**：便ごとの「投げ文」で、先生が決めました。

### Claude（Claude Code）が書いた所
- **コード**：画面（`public/`）、サーバー側の関数（`lib/`・`api/`）、比べ方（`public/js/kurabe.js`）。
- **下書きの文**：問題・選択肢・カードの文・案内・予備の文・Claude への頼み方。どれも「下書き（先生未確認）」の印を付け、先生が確かめる一覧（[docs/先生が確かめる一覧.md](docs/先生が確かめる一覧.md)）に並べています。
- **確かめ**：言葉の点検、比べ方の確かめ、スマホと PC の幅での通し確認、合成データでの確かめ（`scripts/`）。
- **読み上げの音声**：Open JTalk で前もって作りました（`scripts/onsei_tsukuru.py`）。

### 作り方の流れ（1便〜）
1. 先生（と相談チャット）が「投げ文」を書く：その便で作る範囲・守ること・受け入れ条件。
2. Claude Code が作る：コードと下書きの文を書き、決めたことと迷ったことを残す。
3. 自動の確かめ：`npm test`（言葉の点検・比べ方）と `npm run toshi`（画面を最後まで通す）が通ってから、main に入れる。
4. 先生が動作確認をして、下書きを確かめ、次の投げ文を書く。

## 6. 測った結果

**ここに書く数字は、どれも合成データ（コンピュータの中で作った架空の子）と、自動の確かめで出したものです。実際の子どもで確かめたものではありません。効果を示すものでもありません。** 問題の難しさや子どもの力は、制作の側で置いた仮の値です（[docs/合成データでの確かめ.md](docs/合成データでの確かめ.md)、`node scripts/gousei.mjs`）。

表に出てくる言葉の意味です。
- **差が無い合成の子**：読む・聞くなど、どの出し方でも正解のしやすさが同じになるように作った、架空の子。この子に「候補」が出たら、それは「空ぶり」です。
- **差がある合成の子**：聞く・図で見る・一文ずつ区切って出す のほうで、正解しやすくなるように作った、架空の子。おおよそ、ふだん10問中6問できる子が、その出し方なら10問中8問近くできるくらいの差です。
- **候補**：同じ出し方を2回やったときの揺れより大きい差が、同じ向きに2回出たときだけ出すしるし（1回のゲームの中で決まる）。
- **くり返し出た候補**：ある日のゲームで「候補」になり、別の日のゲームでも同じ向きの差が出たときのしるし（3便から）。

### 合成データ：1回のゲームの中で比べたとき（2便）
| 棚 | 正答率の平均 | 5〜8割に入った子 | 差が無い合成の子に「候補」が出た割合 |
|---|---|---|---|
| 読む／聞く | 62.5% | 50.2% | 7.6% |
| 文で見る／図で見る | 54.2% | 46.9% | 8.0% |
| 一気に／区切って | 60.0% | 46.6% | 7.1% |

差が無い合成の子でも、3つの棚のどれかで「候補」が出たのは 21.0%（5人に1人ほど）でした。差がある合成の子でも、1回のゲームで「候補」になったのは、棚ごとに10人に1人ほどでした。だから1回では決めません。

### 合成データ：回をまたいで比べたとき（3便）
比べるのは、その回の中の「出し方の差」どうしです。素点は回ごとに比べません。

| ゲームをした日の数 | 差が無い合成の子に、どれかの棚で「くり返し出た候補」が出た割合 | 差がある合成の子に、どれかの棚で「くり返し出た候補」が出た割合 | （参考）1回ごとに見て、どれかの回・棚で「候補」が出た割合（差が無い子／差がある子） |
|---|---|---|---|
| 1日 | —（1日では出ない） | —（1日では出ない） | 21.4%／28.2% |
| 2日 | 3.6% | 12.8% | 38.5%／46.4% |
| 3日 | 8.5% | 27.1% | 49.1%／60.5% |

1回ごとに見ていくと、差が無い子にも「候補」がたまっていきます（3日で2人に1人ほど）。「くり返し出た候補」にすると、差が無い子に出るのは10人に1人より少ないままで、差がある子は日を重ねるほど見つかりやすくなります（3日で4人に1人ほど）。それでも見のがしは多いので、「候補が出ない」は「差が無い」ではありません。

### 合成データ：仮説が設定どおりだった割合（5便）
合成の子に、別々の日にゲームを3回させ、先生の画面に出る仮説（キーが無いときの予備の文）を読みました。各3,000人。

| 合成の子 | 設定どおりだった割合 | 「設定どおり」の意味 |
|---|---|---|
| 差が無い合成の子 | 93.9% | 「くり返し出た」出し方を挙げなかった（決めつけなかった） |
| 聞くで差がある合成の子 | 10.6% | 聞くを「くり返し出た」として挙げた |
| 図で見るで差がある合成の子 | 6.6% | 図で見るを「くり返し出た」として挙げた |
| 区切って読むで差がある合成の子 | 13.1% | 区切って読むを「くり返し出た」として挙げた |

決めつけない割合は高い一方で、差がある子を3日分で言い当てられる割合は低いままです。仮説に「参考程度・決めるのは先生」を必ず添えるのは、このためです。Claude が書く仮説での割合は、キーが来てから測ります。 この表は **5便の線** で数えたものです（6便で線を比べ、変えなかった。次の表）。

### 線の扱い（6便）：差がある子を、もっと挙げられる線はあるか
上の表のとおり、3日分のゲームでも、差がある合成の子を「くり返し出た候補」として挙げられるのは1割ほどでした。そこで6便では、研究にもとづく骨（揺れより大きい差が同じ向きに2組で「候補」・素点は回ごとに比べない など）は変えずに、「揺れ」の取り方と、別の日の「同じ向き」の数え方を変えた線を、同じ合成の子たち（各3,000人・3日分）で比べました。全部の線は [docs/線の比べ_6便.md](docs/線の比べ_6便.md)。

| 線 | 決めつけなかった割合（差が無い子・3日分） | 1日の空ぶり（差が無い子の1日目に、どれかの棚で「その日の候補」） | 挙げられた割合（差がある子・3日分・3つの棚の平均） |
|---|---|---|---|
| **5便の線（いまの線）**：揺れは2つの出し方の揺れの大きいほう | 91.4% | 21.6% | 10.3% |
| 線1：揺れを2つの出し方の揺れの平均にする | 88.0% | 35.3% | 14.8% |
| 線3：別の日は、2組の差の合計の向きで数える | 70.8% | 21.6% | 21.7% |
| 線6：線1 に加えて、反対向きの差が出た日があれば数えない | 88.3% | 35.3% | 14.7% |
| 線8：5便の線に加えて、反対向きの差が出た日があれば数えない | 91.9% | 21.6% | 10.2% |

**選んだ線：5便の線のまま、変えない。** 骨の中で試せた線では、挙げられる割合は いちばんよくても1.4倍ほど（10% → 15%）でした。その代わりに、1日のゲームで差が無い子に「その日の候補」が出る割合が 2割ほどから3割台に増え、「この日の」カードが根拠の弱いまま渡りやすくなります。数え方をゆるくする線（線3）は、決めつけなかった割合が 7割まで下がります。挙げられる割合をはっきり上げるには、骨の外のこと（1組の問いの数を増やす・長く続けたときの数え方を人で試して決める）が要ります。たとえば図の棚の問いを1場面2問から4問にすると、合成データでは、図で見るで差がある子を挙げられる割合が 6.9% → 14.6% になりました（決めつけなかった割合は 91.4% → 89.2%）。どれにするかは、先生が決めます。

### 難しさの段階（7便・8便）：その子に合う難しさで比べる
はじめの練習の正解率で、段階1（やさしめ）か段階2（ふつう）を選びます。1組目が「ほぼ0」か「全部正解」なら、次の組から段階を変えます（変える前の組は練習扱い）。比べるのは同じ段階の中だけです。合成データ（各3,000人・力の低い子もふくめた）で、選び方を比べました（全部の表は [docs/段階の比べ_7便.md](docs/段階の比べ_7便.md)）。8便で段階1の棚 B の問いを2つにしたので、数字は7便から少し変わりました（7便の表も、その文書に残しています）。

| 選び方 | 比べた問題の正答率が5〜8割に入った割合 | 力の低い合成の子で5〜8割に入った割合 | 決めつけなかった割合（1回のゲーム） |
|---|---|---|---|
| 段階を使わない（いつも段階2） | 38.6% | 0.9% | 78.8% |
| **練習 3/8 以下で段階1（いまの線）** | 52.0% | 23.7% | 78.2% |
| 練習 3/8 以下で段階1・組の途中の切りかえなし | 49.5% | 26.5% | 79.4% |
| 練習 4/8 以下で段階1 | 52.6% | 25.1% | 75.9% |
| （7便：段階1の B が問い1つのとき・いまの線） | 51.9% | 26.8% | 76.5% |

段階を合わせると、力の低い子でも「正解がほとんど無い問題で比べる」ことが減ります。その代わり、決めつけなかった割合は少し下がります。**組の途中の切りかえを入れると、決めつけなかった割合が 79.4%（切りかえなし）から 78.2% に 1.2ポイント下がります**（7便では 79.1% → 76.5%）。この 1.2ポイントの大半は、切りかえた子が新しい問題の組で比べ直す機会が増えることによると考えています（推測で、確かめてはいません）。それでも、正解がほとんど無いまま比べることを避けるために残しています。段階は子どもの画面には出さず、先生の画面にだけ「比べた問題：短い文（途中で変えた）」のように事実で出します。

**段階1の棚 B（8便）**：7便では、段階1の B は問い1つ×2組（1つの出し方あたり2問）で、4択なので当てずっぽうでも差が付きやすく、根拠が薄いものでした。合成データ（各6,000人・力の低い子を多めに）で直し方を比べ、問いを2つにしました（段階2と同じ形の「代金が分かったときの式」を足した）。

| 直し方 | 決めつけなかった（差が無い子・B） | 決めつけなかった（差が無い子・3つの棚ぜんぶ） | 挙げられた（図で差がある子・B） |
|---|---|---|---|
| 7便のまま（問い1つ） | 87.0% | 76.2% | 17.8% |
| **(a) 問いを2つにする（選んだ）** | 91.7% | 78.1% | 10.3% |
| (b) 問い1つのまま、差の合計3以上 | 100.0% | 83.7% | 0.0% |
| (a)＋(b) | 99.3% | 83.4% | 1.5% |

（12便で、棚 B の中身を「x 個買って代金の式」から生活の場面（教室の席・校舎の案内図・時間割・ロッカーの上の棚）の文／図の問題に差し替えました。中1の数学の問題に見えて「教科に持ち込まない」と合わなかったためです。問いの数と段階の作りは同じなので、この表は8便のままです。）(a) で「決めつけなかった」は上がりました。**挙げられた割合が 17.8% から 10.3% に下がったのは、当てずっぽうで付いた差を候補に数えなくなったためと読めます**（差が無い子に B で候補が出た空ぶりも、13.0% から 8.3% に減りました）。問い1つのときは、差1問・揺れ0問で候補になるゆるさがありました。(b) は候補がほとんど出なくなるので選びませんでした。

### 子どもの画面の文字の量（12便）

### 練習の段が進む決まり（7便）：確かめ
合成データではなく、決まりそのものを確かめました（`npm test`）。「正解が多い（3分の2以上）」ひとつが同じ段で2回続くと次の段へ進み、間に少ないひとつがあると数え直し、日をまたいでも続けて数え、下がらず、段4 で止まること。読む・聞くの段3 では、支えのボタンを3回以上押したひとつは数えないこと。読み上げが使えなかったひとつは数えないこと。練習の効果（学力への）は確かめていません。

### 難しかった所
**1回のゲームでは、決められないこと。** 合成データで確かめると、差が無い子でも、1回のゲームの3つの棚のどれかで「候補」が出るのが5人に1人ほどありました。「候補」を出す線を厳しくすると、本当に差がある子がほとんど見つかりません。そこで、1回の中の線はそのままにして、「別の日にも同じ向きの差が出たか」を重ねて見る決まり（くり返し出た候補）にしました。同じ日に2回やっても数えません。2回目は慣れて正解が増えやすいので、素点は回ごとに比べず、その日の中の差どうしで比べます。6便では、骨を変えずに線を12通り比べましたが、差がある子を挙げられる割合を大きく上げる線はありませんでした。少ない問いの数で「決めつけない」と「見つける」の両方を高くすることは、できないと分かったことが、いちばん難しかった所です。

## 8. 限界

- 標準化された検査ではありません。本人の中で比べるだけです。
- どの出し方も、効く子もいれば効かない子もいます。差が出ないのも、ふつうの結果です。
- 1回の結果では決めません（[docs/作り方の決まり.md](docs/作り方の決まり.md)）。
- チェック項目は点数にしません。当てはまったことは「気づきの候補」として残るだけです。
- 実際の子どもでの確かめは、これからです。ここに書いた数字は、どれも合成データか自動の確かめです。
- 問題の難しさ（正答率5〜8割になるか）と、1回のゲーム・朝の練習にかかる時間は、まだ人で測っていません。
- 12便で差し替えた棚 B（生活の場面）の難しさと、短くした子どもの画面の文の読みやすさは、まだ人で確かめていません。
- 朝の練習の効果（学力への）は確かめていません。言えるのは「ゲームの中で、支えが少なくてもできる量が増えた」までです。段が進む決まり（3分の2以上・2回続けて）も、仮の値です。
- 書いて答える・口で答える出し方は、比べる棚が無いので測っていません（そのカードは期間中は出しません）。
- 組の途中で難しさの段階を切りかえると、差が無い子を決めつけなかった割合が 1.2ポイントほど下がります（合成データ。くわしくは測った結果の段階の節）。
- カードは「出し方の3つの比べ」だけを表すものです。得意・不得意の全体を表すものではありません。
- Claude が実際に書く文（次を選ぶ理由・仮説・伝え方）は、API キーが無いため、まだ見ていません。今は決まった順・決まった文の「予備の動き」で動いています。
- 「候補が出ない」は「差が無い」ではありません。3日分のゲームでも、見のがしは多くあります。
- 記録は端末のブラウザの中だけにあります。端末を変えると、続きは見られません。

## 9. 動かし方

1. Node.js 20 以上を入れて、このフォルダで `npm install` を実行する。
2. Claude を使うときは、`.env.example` を `.env` に写し、`ANTHROPIC_API_KEY` を入れる（`.env` は Git に入れない）。キーが無くても、決まった順の予備の動きで最後まで動きます。
3. `npm start` を実行し、ブラウザで `http://localhost:8787` を開く。
4. はじめの画面から、「保存した結果を見る」（架空の子8人：1回だけの子・3日分の記録がある子・練習でカードが育った子・やさしい段階で比べた子）か「その場で動かす」を選ぶ。

確かめ方：
- `npm test`：言葉の正本による点検（画面・サーバー側・予備の動きの文）と、比べ方の確かめ。
- `npm run toshi`：スマホの幅と PC の幅で ①〜⑦ を最後まで通し、各画面の文を点検する（Playwright と Chromium が要る）。
- `npm run douga`：動画用の画面写しを `docs/動画素材/` に作る。
- `node scripts/gousei.mjs`：合成データ（実在の子どもではない）で、正答率と「候補」の決まりのふるまいを見る。結果は [docs/合成データでの確かめ.md](docs/合成データでの確かめ.md)。
- 読み上げの音声は、前もって作ったもの（Open JTalk・声 “Mei”・CC BY 3.0）を使います。作り直すときは `scripts/onsei_tsukuru.py`。

カードの名前・副題・レベルの名前は [public/data/card_namae.json](public/data/card_namae.json) の1つにまとめてあります（仮の名前。名前を変えるときは、このファイルの「名前」だけを書きかえます）。学校の設定のはじめの値は [public/data/gakko.json](public/data/gakko.json) です。

公開の手順は [docs/デプロイの手順.md](docs/デプロイの手順.md)。先生が確かめる下書きの一覧は [docs/先生が確かめる一覧.md](docs/先生が確かめる一覧.md)。
