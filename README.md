# チカラのスイッチ

> 【下書き】このファイルは開発の最初に置いた骨組みです。【あとで書く】の所は、作りながら埋めます。副題は未定です。

困りごとを自分では言葉にできない子に、「分かってもらえる機会」を作るアプリです。
中学生が授業の中で短いゲームをして、力が出た出し方が「スイッチカード」として手元に残ります。先生には、配慮の手がかりが残ります。

「学び方の型を当てる」ものではありません。同じ問題を出し方だけ変えて解いてみて、**どの出し方のとき力が出たか**を、本人の結果で確かめます。医療や専門の検査の代わりでもありません。その手前を受け持ちます。

---

## 1. 困りごと

**困っていたのに、機会がなければ、何も解決せずに過ぎていく。**

「困ったら言ってね」と言っても、自分から言える子はほとんどいません。でも、たくさん質問すると答えてくれます。解けているのにノートは白紙、国語は苦手でも図は描ける――そういう子は、どの教室にもいます。

- 文部科学省の2022年の調査では、通常の学級の小中学生のうち、学習面や行動面で著しい困難があると担任などの教員が回答した子は、推定 8.8%（中学校は 5.6%）でした。そのうち、校内委員会で特別な教育的支援の対象とされているのは 28.7% です。
  - この数字は教員の回答にもとづく推定で、医師の判断にもとづく数ではありません。
- 専門の医療機関では、初診まで数か月待つことがあります。総務省の2017年の調査では、半数以上の機関で3か月以上待ち、最長は約10か月でした。
- 制度の上では、医師の判断がなくても配慮はできます。文部科学省は、通級による指導を決めるとき、医学的な判断があるかどうかだけで決めず、総合的に考えるよう求めています（2013年の通知）。でも現場では、根拠がないと動けません。
- 個に応じた指導は、気づいた先生には当たり前です。でも学校全体では、まだ当たり前になっていません。

## 2. 何をするか

月に1回、授業やホームルームで、一人ひとりが短いゲームに取り組みます（合計10分以内。分けてもできます）。同じ難しさの問題を、出し方を変えて解きます。一つ一つの出し方を「スイッチ」と呼びます。

1. **案内**：何をするか、何をしないかを、子どもと保護者に先に伝えます。
2. **ゲーム**：「読んで答える」「聞いて答える」「図を見て答える」などに取り組みます。途中に、困りごとの言葉を代わりに用意した質問があり、タップで答えます。次にどのスイッチを試すかは、Claude が理由をつけて選びます。
3. **スイッチカード**：力が出た出し方が、カードとして残ります。カードには「これは何か」「自分でできる使い方」「先生にお願いしてよいこと」が書いてあります。
4. **先生の画面**：その子の中での比べ方、選んだ答え、先生が期末に見るチェック項目で当てはまったこと、そして Claude の仮説（理由つき・参考程度）を見ます。
5. **伝え方**：懇談で先生が口で言うための下書きと、求められたときに渡すカードの説明を、Claude が下書きします。決めるのは先生です。
6. **学習につなぐ**：先生が作った問題を、見つかった出し方で出し直します。

子どもには、力が出たことだけが残ります。他の子との比べっこはしません。

## 4. 仕組み（Claude の三段の役割）

| 段 | だれが決めるか | 内容 |
|---|---|---|
| 次に何を出すか | Claude | 問題の棚は固定（先生が確かめた自作）。結果を見て、次に試すスイッチを理由つきで選ぶ。理由は画面に出す |
| 仮説を出す | Claude | ゲームの結果・選んだ答え・チェック項目を並べて読み、「〇〇のとき力が出ているかも。次に試すなら△△」と書く。決めつける言葉は使わない。仮説・確かめた回数・参考程度を必ず添える |
| 言葉を書く | Claude（決めるのは先生） | カードの文、先生の口頭の下書き、保護者向けの説明。言葉の正本で機械的に点検し、避ける言葉が出たら書き直す |

## 5. Claude の使い方

- 言葉の正本（[data/言葉の正本.json](data/言葉の正本.json)）を Claude に持たせます。避ける言葉が出力に出たら機械的に見つけ、書き直させます。
- 子どもが自由に文を打って Claude と会話する入口はありません。質問は選んで答える形です。
- AI を使っていることは、画面に表示します。
- 先生の画面の言葉も、保護者が読んで傷つかない言葉で書きます（事実・試した工夫・その結果）。
- キーが無いとき・使えないときは、決まった順・決まった文の「予備の動き」で最後まで動きます。

### 人が決めた所（先生と相談チャット）
- **題材と、だれのための何か**：困りごとを自分で言葉にできない中学生に「分かってもらえる機会」を作ること。
- **守ること**：避ける言葉（言葉の正本）、決めつけないこと（型や結論の名前を付けない）、効果をうたわないこと、子どもが自由に文を打つ入口を作らないこと、実在の子のデータを入れないこと、既存の検査に似る形を置かないこと。
- **ゲームの棚**：読む／聞く・文で見る／図で見る・一気に／区切って・選んで答える質問（制作の入口 06 の3章。棚 E は作らない）。
- **カード**：強みだけ、全員に1枚以上、枚数は出さない、「〇〇スイッチ」の名前、「この日の」結果だと分かる書き方（06 の4章）。
- **チェック項目**：18項目（06 の5章）。点数にしない。
- **比べ方の決まり**：本人の中だけで比べる、初回は練習、ABBA、揺れより大きい差が2回で「候補」、回をまたぐときは別の日の「くり返し」（[docs/作り方の決まり.md](docs/作り方の決まり.md)）。
- **どこまで作るか・何を後にするか**：便ごとの「投げ文」で、先生が決めました。

### Claude（Claude Code）が書いた所
- **コード**：画面（`public/`）、サーバー側の関数（`lib/`・`api/`）、比べ方（`public/js/kurabe.js`）。
- **下書きの文**：問題・選択肢・カードの文・案内・予備の文・Claude への頼み方。どれも「下書き（先生未確認）」の印を付け、先生が確かめる一覧（[docs/先生が確かめる一覧.md](docs/先生が確かめる一覧.md)）に並べています。
- **確かめ**：言葉の点検、比べ方の確かめ、スマホと PC の幅での通し確認、合成データでの確かめ（`scripts/`）。
- **読み上げの音声**：Open JTalk で前もって作りました（`scripts/onsei_tsukuru.py`）。

### 作り方の流れ（1便〜）
1. 先生（と相談チャット）が「投げ文」を書く：その便で作る範囲・守ること・受け入れ条件。
2. Claude Code が作る：コードと下書きの文を書き、決めたことと迷ったことを残す。
3. 自動の確かめ：`npm test`（言葉の点検・比べ方）と `npm run toshi`（画面を最後まで通す）が通ってから、main に入れる。
4. 先生が動作確認をして、下書きを確かめ、次の投げ文を書く。

## 6. 測った結果

**ここに書く数字は、どれも合成データ（コンピュータの中で作った架空の子）と、自動の確かめで出したものです。実際の子どもで確かめたものではありません。効果を示すものでもありません。** 問題の難しさや子どもの力は、制作の側で置いた仮の値です（[docs/合成データでの確かめ.md](docs/合成データでの確かめ.md)、`node scripts/gousei.mjs`）。

表に出てくる言葉の意味です。
- **差が無い合成の子**：読む・聞くなど、どの出し方でも正解のしやすさが同じになるように作った、架空の子。この子に「候補」が出たら、それは「空ぶり」です。
- **差がある合成の子**：聞く・図で見る・一文ずつ区切って出す のほうで、正解しやすくなるように作った、架空の子。おおよそ、ふだん10問中6問できる子が、その出し方なら10問中8問近くできるくらいの差です。
- **候補**：同じ出し方を2回やったときの揺れより大きい差が、同じ向きに2回出たときだけ出すしるし（1回のゲームの中で決まる）。
- **くり返し出た候補**：ある日のゲームで「候補」になり、別の日のゲームでも同じ向きの差が出たときのしるし（3便から）。

### 合成データ：1回のゲームの中で比べたとき（2便）
| 棚 | 正答率の平均 | 5〜8割に入った子 | 差が無い合成の子に「候補」が出た割合 |
|---|---|---|---|
| 読む／聞く | 62.5% | 50.2% | 7.6% |
| 文で見る／図で見る | 54.2% | 46.9% | 8.0% |
| 一気に／区切って | 57.7% | 46.9% | 7.2% |

差が無い合成の子でも、3つの棚のどれかで「候補」が出たのは 21.0%（5人に1人ほど）でした。差がある合成の子でも、1回のゲームで「候補」になったのは、棚ごとに10人に1人ほどでした。だから1回では決めません。

### 合成データ：回をまたいで比べたとき（3便）
比べるのは、その回の中の「出し方の差」どうしです。素点は回ごとに比べません。

| ゲームをした日の数 | 差が無い合成の子に、どれかの棚で「くり返し出た候補」が出た割合 | 差がある合成の子に、どれかの棚で「くり返し出た候補」が出た割合 | （参考）1回ごとに見て、どれかの回・棚で「候補」が出た割合（差が無い子／差がある子） |
|---|---|---|---|
| 1日 | —（1日では出ない） | —（1日では出ない） | 21.0%／28.5% |
| 2日 | 3.5% | 13.0% | 38.3%／46.4% |
| 3日 | 8.7% | 27.5% | 49.3%／60.6% |

1回ごとに見ていくと、差が無い子にも「候補」がたまっていきます（3日で2人に1人ほど）。「くり返し出た候補」にすると、差が無い子に出るのは10人に1人より少ないままで、差がある子は日を重ねるほど見つかりやすくなります（3日で4人に1人ほど）。それでも見のがしは多いので、「候補が出ない」は「差が無い」ではありません。

### 自動の確かめ
- 言葉の点検（言葉の正本の「避ける言葉」）：画面とサーバー側のファイル 4,696 行・予備の動きの文 1,565 件・制作が書いた文書 358 行・この README で、避ける言葉は 0 件（`npm test`）。
- 比べ方・カード・回をまたいだ比べ方・Claude の呼び方などの確かめ：27 件が通過（`npm test`）。
- スマホの幅（375px）と PC の幅（1280px）で、①〜⑥・2回目のゲーム・架空の子6人を通す確かめ：97 画面・3,382 行で、避ける言葉 0 件・横へのはみ出し 0 件（`npm run toshi`）。
- 実際の子ども・大人での確かめは、まだしていません。

## 8. 限界

- 標準化された検査ではありません。本人の中で比べるだけです。
- どの出し方も、効く子もいれば効かない子もいます。差が出ないのも、ふつうの結果です。
- 1回の結果では決めません（[docs/作り方の決まり.md](docs/作り方の決まり.md)）。
- チェック項目は点数にしません。当てはまったことは「気づきの候補」として残るだけです。
- 実際の子どもでの確かめは、これからです。

## 9. 動かし方

1. Node.js 20 以上を入れて、このフォルダで `npm install` を実行する。
2. Claude を使うときは、`.env.example` を `.env` に写し、`ANTHROPIC_API_KEY` を入れる（`.env` は Git に入れない）。キーが無くても、決まった順の予備の動きで最後まで動きます。
3. `npm start` を実行し、ブラウザで `http://localhost:8787` を開く。
4. はじめの画面から、「保存した結果を見る」（架空の子2人）か「その場で動かす」を選ぶ。

確かめ方：
- `npm test`：言葉の正本による点検（画面・サーバー側・予備の動きの文）と、比べ方の確かめ。
- `npm run toshi`：スマホの幅で ①〜⑥ を最後まで通し、各画面の文を点検する（Playwright と Chromium が要る）。
- `node scripts/gousei.mjs`：合成データ（実在の子どもではない）で、正答率と「候補」の決まりのふるまいを見る。結果は [docs/合成データでの確かめ.md](docs/合成データでの確かめ.md)。
- 読み上げの音声は、前もって作ったもの（Open JTalk・声 “Mei”・CC BY 3.0）を使います。作り直すときは `scripts/onsei_tsukuru.py`。

公開の手順は [docs/デプロイの手順.md](docs/デプロイの手順.md)。先生が確かめる下書きの一覧は [docs/先生が確かめる一覧.md](docs/先生が確かめる一覧.md)。

デモのデータは、すべて架空の子どものものです。
